Все три `robots.txt` доступны HTTP 200 и ссылаются на собственную карту сайта. Это допустимая конфигурация **трёх независимых хостов**. Отсутствие 870 записей в sitemap главной само по себе не ошибка: модели находятся на **другом хосте**.

В Supabase `public.phone_models` **870 моделей**. Каталог публикует в sitemap 715 модельных URL, что на **155 меньше**, чем всего записей в модели БД. Это **не значит, что все 155 непременно пропущены ошибочно**: нужны сверка действующих URL, доступности и опубликованности, а не автоматическое добавление несуществующих страниц.

### Обнаруженный технический недостаток

Для живой страницы `/phones/nokia/1110?lang=hy` сервер возвращает `<html lang="hy">` и армянский заголовок, **но rel=canonical указывает на русскую страницу без lang**, `hreflang` отсутствует. Та же проблема для `?lang=en`. Google может воспринять эти вариации как неканонические и не выбирать нужную версию при поиске. Для страницы Nokia 1110 из истории брендов `?lang=hy` самоадресный canonical и `hreflang` **уже есть**, её не меняем.

Для корня главного сайта `?lang=hy` и каталога `?lang=en` сервер пока отдаёт русский `<html lang="ru">` и русский заголовок, затем интерфейс может меняться JavaScript-ом. **Нельзя добавлять hreflang на такие URL**, пока сервер реально не отдаёт отдельный переведённый основной текст, иначе поисковик получит ложную языковую метку.

В старом `catalog-proxy/api/proxy.js` есть функция, способная генерировать hreflang для подтверждённой многоязычной редакционной истории, но она неправильно выдавала `?lang=ru` вместо одного базового русского canonical и не исправляла `canonical` у HY/EN. **В этой ветке код исправлен** только для полностью переведённых опубликованных моделей:
- RU: `/phones/nokia/1110` — canonical и hreflang ru;
- HY: `/phones/nokia/1110?lang=hy` — self canonical + hreflang hy;
- EN: `/phones/nokia/1110?lang=en` — self canonical + hreflang en;
- x-default: RU canonical;
- Reciprocal hreflang вставлять, только если все 3 полноценных текста действительно подготовлены; иначе оставлять только корректный self canonical.
- CSS, HTML корпуса страницы, фото, цены и права доступа не изменять.

**Важное ограничение:** текущий каталог развернут на отдельном проекте, полные точные исходники активной production-сборки ещё требуют сверки. Код в GitHub **не означает** автоматического изменения текущего сайта. Прежде чем развернуть, сравнить активные исходники, отладить в отдельном тестовом проекте, проверить выбранную каноническую схему и наличие реальных переводов для каждой страницы.

## Безопасная схема улучшения

1. **Оставить три собственных sitemap** с собственными robots.txt; зарегистрировать/проверить права на каждый Vercel-хост в Google Search Console и отправить каждую карту. Межхостовый единый sitemap допустим только после проверки прав на все сайты; без этого использовать независимые.
2. **Каталог:** сверить 715 карточек из sitemap с реальными моделями и выявить до 155 оставшихся, которые действительно готовы к поисковой индексации. Исключить черновики и отсутствующие URL.
3. **Языки:** внедрить self canonical и взаимные hreflang для настоящих HTML-переводов. Для главной/корня каталога/новостей сначала решить серверную отдачу содержимого по ru/hy/en, не выдавать JS-переключение за индексируемые самостоятельные локализации.
4. **Дубликаты:** оценить пересечения `nokia-1110.html` на главном сайте и `/phones/nokia/1110` в каталоге; согласовать один предпочтительный URL, но не удалять страницы и не делать редиректы без проверки содержания.
5. **QA:** проверка XML, HTTP-статусов и канонических ссылок на каждой версии, отсутствие 404/500, точные reciprocal hreflang, отсутствие утечек секретов. Только после этого безопасный релиз.
