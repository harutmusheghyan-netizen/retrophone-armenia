# RetroPhone Armenia — контроль ежедневной публикации трёх новостей

Дата изменения: **8 ноября 2026 года, Ереван**. Это изменение настроек **существующего** задания, не новый AI-агент и не изменение боевого сайта.

## Исходная проверка

- На 8 ноября 2026 года, около 05:15 по Еревану, в `public.retro_news_posts` находятся **26 опубликованных** новостей.
- Все 26 имеют тексты RU/HY/EN, заполненные image_url, image_source_url, image_author, image_license, source_url и verified_at. **Фактическая загрузка каждой фотографии на стороне посетителя отдельно не доказана.**
- **0 записей с video_url**, 0 записей в `retro_news_edit_drafts`.
- Последняя публикация: **7 ноября 2026, 20:45 Ереван** (16:45Z), ID 27.
- Публикации 1–7 ноября: 3, 3, 0, 0, 0, 0, 1, всего 7 вместо 21.
- Публичные `/news/`, `/news/archive/`, `/api/retro-news?limit=5` проверены HTTP 200.
- В Supabase `pg_cron` сейчас нет собственного задания импорта новостей. Задача публикации управляется **существующей автоматизацией ChatGPT**.
- Исходное расписание: один запуск в день в 09:00 по Еревану, `flexible_schedule`.
- Прямая запись в защищённую таблицу может публиковаться без нового развёртывания Vercel, **только при соблюдении всех лицензий и редакционных ограничений**.
- Результат запуска задачи 7 ноября: задача запустилась примерно 09:44 по Еревану, нашла источники, но **не опубликовала ничего, потому что не смогла подтвердить загрузку лицензированных изображений**. Не утверждаем, что это единственная причина пропусков 3–6 ноября.

## Реально внесённое изменение

Обновлена **исходная задача**, ID `6ae0c7ac6d6c81919ce7608d242f1c19`, «Ежедневно 3 разные новости RetroPhone». Состояние после изменения: **enabled=true**.

Новое расписание:
```ical
BEGIN:VEVENT
DTSTART:20261108T090000
RRULE:FREQ=DAILY;BYHOUR=9,14,19;BYMINUTE=0
END:VEVENT
```
Часовой пояс `Asia/Yerevan`. Фактическое выполнение может немного сдвигаться, так как текущий режим задачи — flexible_schedule.

- Перед каждой попыткой подсчитываются публикации за **текущий день по Еревану**. Если уже 3 — новая запись не публикуется.
- Если до трёх не хватает: проверяются **6–9 реальных кандидатов** из различных направлений (AI, телефоны/сети, смартфоны/технологии), источники и даты; публикаций не больше недостающего количества.
- Для изображения проверяется лицензия Wikimedia Commons и фактическая доступность; при отсутствии снимка события допустим проверенный логотип той же компании. При неудаче после трёх попыток переключение на **другой реальный сюжет**, а не остановка всего выпуска.
- RU/HY/EN заголовки, лиды, полные статьи и подписи к изображениям должны быть содержательными и согласованными, а slug, source_url и событие — не повторять уже опубликованные.
- После реальной вставки: SELECT в Supabase, API, `/news/`, архив. Нельзя объявлять успех на основании одного HTTP 200 без проверки записи.
- В каждом запуске фиксировать: счёт 0–3, реальный прирост, источники, ссылку на новость, причину ошибок, остаток дневного плана.
- Если не найдены три **достоверных лицензированных** материала, выпускать меньше и честно сообщать; **не подделывать новости ради числа три**.

### Оставшиеся фактические проверки

1. **Проверить выполнение ближайших запусков 8 ноября** и количество свежих строк, а не только статус задания.
2. Подтвердить визуальную загрузку изображений, лицензию и привязку логотипа к нужному бренду.
3. Проверить реальный цикл «новость обнаружена → верификация → оригинальные тексты RU/HY/EN → публикация → API → видимый материал».
4. При повторных блокировках посмотреть результаты запусков автоматизации и логи; исправлять только подтверждённые причины.

## SQL для контроля (чтение)

```sql
select (published_at at time zone 'Asia/Yerevan')::date as day,
       count(*)::int as published
from public.retro_news_posts
where status='published'
  and published_at >= now() - interval '14 days'
group by 1 order by 1 desc;

select count(*)::int as published_today
from public.retro_news_posts
where status='published'
and (published_at at time zone 'Asia/Yerevan')::date
    = (now() at time zone 'Asia/Yerevan')::date;
```
